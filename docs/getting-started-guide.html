1 AIDD là gì?

Mục tiêu chính: dùng bộ công cụ Takumi Agent Kit phối hợp Claude Code để chuyển Design + Spec thành code.

🎯 Input → Output

Input: Design trên Figma + Screen Specs trên MoMorph.
Output: Source code hoàn thiện (UI + logic + test).

📐 Nguồn sự thật (source of truth)

Figma = chuẩn cho UI (màu, spacing, size — không đoán).
MoMorph Spec = chuẩn cho logic (validation, flow, error state).

Các use case mở rộng (khuyến khích thử)

🧩 MoMorph Support

Gen UI specs & test cases tự động lên MoMorph.

🔄 Reverse Engineering

Gen ngược tài liệu spec từ source code dự án cũ.

⚡ Pre-project

Tăng tốc Estimate & làm Prototype khi bidding.

🛠️ Customization

Tự thiết kế Agent / Flow riêng cho bài toán đặc thù.

4 Chọn đúng Scenario (quan trọng!)

Tùy độ phức tạp mà chọn 1 trong 4 cách. Đừng dùng dao mổ trâu để cắt tiết gà.

Scenario 1 Simple / medium feature

Scope rõ, vài phút → 1–2 ngày, không cần review plan trước.

/tkm:takumi <MoMorph Screen URLs>

Takumi đọc spec + test case, hỏi phần mơ hồ, viết code khớp pattern project. Reviewer tự chạy. 1 command → 1 PR.

Scenario 2 Complex feature

Subsystem mới, nhiều màn, chạm core infra — cần review scope trước.

/tkm:create-plan <URLs>   # tạo plan
# review, chỉnh sửa...
/tkm:takumi plans/.../plan.md

Chia feature thành nhiều phase có acceptance criteria, thực thi từng phase kèm checkpoint.

Scenario 3 UI only

Chỉ cần biến design thành UI component — không backend, không logic.

/momorph-implement-design <URLs>

Đọc design qua MCP, lấy visual chính xác (không đoán), gen UI với mock data từ chính design, chạy visual validation loop tới khi khớp.

Scenario 4 Fix a bug

Code màn đang có bug — UI/logic sai, thiếu validation, hoặc spec đã update mà code chưa theo.

/tkm:fix-bug <mô tả bug> <URL>

Diff code với design + spec + test case → xác định file:line lệch → patch tối thiểu → chạy lại test verify trước khi commit.

5 Flow implement (khi gọi /tkm:takumi)

Điểm đặc biệt của MoMorph: UI và Logic chạy song song 2 track, không chờ nhau.

① DETECT & RESOLVETách fileKey + screenId từ URL
↓
② FETCH — song song, qua MCPget_frame · download_specs · download_test_casesNgay khi xong → tách 2 track chạy song song
↓
🎨 TRACK A — UI (subagent nền)
  1. Đọc design qua MCP
  2. Lấy visual CHÍNH XÁC — không đoán màu / px
  3. Mock data lấy từ Figma
  4. Dựng component (shadcn + Tailwind)
  5. Visual validation loop so Figma reference
⚙️ TRACK B — Logic (main thread)
  1. ③ Deep-read spec + test case (từng dòng)
  2. ④ Cross-ref → tìm gap (error, validation, navigation, empty/loading...)
  3. ⑤ Clarify → ghi clarifications.md
  4. ⑥ Plan backend (API, data model, Supabase)
  5. ⑦ Implement backend / logic
↓
⑧ INTEGRATION — không có merge cứng. Track A xong màn nào → thay mock data bằng Supabase thật, nối event handler, wire TanStack Query + Zustand.
↓
⑨ TESTING (TDD)Vitest (unit) + Playwright (E2E)chạy theo test cases MoMorph
↓
⑩ INSPECTIONReviewer agent (tự động)
↓
⑪ DELIVERY1 command → 1 PR
🚧 Gate ⑤ Clarification là cửa chặn bắt buộc. Takumi PHẢI dừng hỏi bạn trước khi code logic — không được đoán. Câu trả lời được ghi vào clarifications.md và không hỏi lại.
🧵 Nhiều màn (N screens): Track A spawn N subagent nền song song (mỗi màn 1 agent, không share state). Track B ở main thread xử lý clarify → plan → backend cho từng màn.

7 Definition of Done

Một bài thực hành đạt chuẩn phải đủ 3 tiêu chí:

🎨 UI

Chính xác tuyệt đối so với Design Figma (pixel-perfect).

⚙️ Logic

Hoạt động đúng theo Screen Specs trên MoMorph.

✅ Quality

Đầy đủ Unit Test + E2E Test theo quy trình TDD.

8 Bắt đầu như thế nào?

Lộ trình đề xuất cho người mới — verify flow với 1 màn trước, rồi nhân rộng.

  1. Kiểm tra kết nối MoMorph MCP — hỏi Claude Code "đọc được MoMorph của source này không?" để chắc MCP server hoạt động.
  2. Xem CLAUDE.md — đọc để nắm stack & convention đã chốt (Next.js + shadcn + Supabase + Vitest/Playwright).
  3. Chạy thử màn Login (Scenario 1) — màn đơn giản, có sẵn trong README làm ví dụ: 
    /tkm:takumi Implement the login page (/login), use Supabase local project:
https://momorph.ai/files/9ypp4enmFmdK3YAFJLIu6C/screens/GzbNeVGJHz
  4. Quan sát flow chạy thực tế — để ý gate Clarification (Takumi dừng hỏi), Track A/B song song, rồi test + review tự động.
  5. Nhân rộng — khi quen flow, dùng /tkm:create-plan (Scenario 2) cho nhiều màn cùng lúc.
